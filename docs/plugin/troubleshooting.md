# Troubleshooting

Start with the CLI: `validate`, `policy`, `dev` give deterministic error codes. The host logs load failures with
a failure kind and a stable message; per-plugin logs live under the App's log sink.

## Manifest / validation

| Symptom | Cause / fix |
|---|---|
| `manifest.id.reserved` | id is a platform name (`system`, `settings`, …) — pick another |
| `manifest.id.invalid` or folder mismatch | id must be `^[a-z0-9]([a-z0-9-]{0,38}[a-z0-9])?$` and equal the `<id>` folder |
| `manifest.apiVersion.unsupported` | plugin built for another SDK major (host supports 2.x); rebuild against `FluidBar.Sdk` 2.x |
| `manifest.maxAppVersion.beforeMin` | fix `maxAppVersion >= minAppVersion` |
| `manifest.locales.default.notAvailable` | `locales.default`/`fallback` must be listed in `available` |
| `manifest.capability.reason.missing` | add a plain-language `reason` (≥10 chars) to network/files/shell/process/registry/hotkeys |
| `manifest.contributes.layout.slot.unknown` | slot name is not valid for that template — see `docs/plugin/declarative-ui.md` |
| `manifest.contributes.layout.id.namespace` | contribution ids must start with `<plugin-id>.` |
| `manifest.contributes.setting.key.duplicate` | setting keys must be unique across all pages/groups |
| `manifest.dependencies.sdk.unsatisfied`/`invalid` | dependency range not satisfied by host SDK or unsupported syntax (`^`, `~`, comparators, `\|\|`) |
| Unknown manifest property | strict parser rejects typos; check `schemas/plugin.schema.json` |

## Build / packaging

| Symptom | Cause / fix |
|---|---|
| `Packages must not bundle FluidBar.Sdk.dll` | SDK reference must be `Private="false"`; never copy the SDK into `plugin/` |
| `package.forbiddenAssembly`/`forbiddenReference` | WPF/Avalonia/WebView2/`FluidBar.App`/host references are forbidden. Note `const` strings can be inlined — the scan also checks shipped file names + deps.json |
| `package.entry.notFound` | `entry.assembly` must be a package-relative `plugin/….dll` and actually packaged |
| `No .deps.json next to the entry assembly` | set `EnableDynamicLoading=true` on the plugin csproj |
| `package.depsJson.sharedSdk` warning | expected: the deps file lists the shared SDK; shipping the DLL is what fails |
| Packaging is not deterministic | fixed timestamps/sorted entries are generated by the CLI; a custom packer or post-processing ZIP step breaks the hash |
| `checksums.json` mismatch / `not covered by checksums` | package was modified after packing; repack with `fluidbar-plugin pack` |
| `Locale bundle consistency failed` | translate placeholders exactly (`{name}`, plural branches) and keep `en-US` complete |
| `Entry assembly … was not found in '<staging>'.` | build the plugin first (CLI expects `bin/<config>/net10.0` output with `manifest.json`/`locales` copied) |

## Loader / lifecycle

| Symptom | Cause / fix |
|---|---|
| `Incompatible` | apiVersion major mismatch or `minAppVersion`/`maxAppVersion` excludes this App version |
| `EntryTypeMissing` | `entry.type` typo or namespace change; rebuild after renaming |
| `EntryTypeInvalid` | entry type does not implement `IFluidBarPlugin` from the **host** SDK (check for a smuggled SDK copy / wrong assembly) |
| `ConstructorFailed`/`InitializeFailed`/`StartFailed` | exception in your lifecycle code; see host log; ensure `StartAsync` never blocks |
| `Timeout` | `InitializeAsync`/`StartAsync` must complete quickly (5 s host default); move long work to leases/background tasks |
| Plugin loaded then `Disabled` | too many consecutive failures; fix the root cause and re-enable (counter resets on successful start) |
| `restartRequired=True` on unload | something keeps the ALC alive: undisposed `Timer`/threads, a **host-owned static event** (SDK has none — don't subscribe to app statics), static events in a host library, or a P/Invoke/native handle. Dispose timers in `StopAsync` or register them via `context.RegisterForDisposal`; see `docs/rewrite/research/06-plugin-alc-spike.md` |
| `Collected=False` after unload but no obvious leak | check `AssemblyLoadContext` usage, exceptions retained in fields (never store plugin `Exception` objects in host state), and long-running tasks that capture `this` |
| Windows file lock: cannot delete/update the plugin folder | a loaded DLL is mapped. Stop the plugin and let unload collect first; updates use versioned directories (never in-place replacement). If still locked, restart FluidBar |

## Marketplace / signatures

| Symptom | Cause / fix |
|---|---|
| `SignatureInvalid` / hash mismatch | package or `signature.json` was modified, wrong signer, or the index advertises another hash. Repack + re-sign; never re-zip a signed package |
| `key … is not trusted` | client trust store lacks the signing `keyId`; maintainers must publish the public key in `keys.json`/compiled-in trust before signing |
| `key … was revoked` / expired / not yet valid | rotate keys; see [signing-and-keys.md](signing-and-keys.md) |
| `Index rollback detected` | index `generatedAt` older than the client cache; redeploy the newer index/check clock |
| `generatedAt … future` | CI clock skew; ensure the runner clock is synced |
| `verify-index FAILED` | wrong `keys.json`, index edited after signing, or canonicalization changed — regenerate with `publish-prepare` |
| `activation failed` during install | the host could not load/start the new version; the previous version stays active. Check the host log, then `verify-index`/`dev` |
| Install refused: `Unsigned install is not allowed` | marketplace installs require the countersignature; offline installs need explicit "install unverified" consent |

## CI / workflow

| Symptom | Cause / fix |
|---|---|
| Publish job fails: signing key env empty | configure the `MARKETPLACE_SIGNING_KEY_PEM` environment secret (placeholder name) — see [signing-and-keys.md](signing-and-keys.md) |
| Pages deploy fails but artifact exists | Pages is disabled/unavailable: download the `marketplace-site` workflow artifact and host it manually; the index is self-contained |
| Validate job cannot find plugin build output | the workflow builds Release first; CLI expects `plugins/<id>/bin/Release/net10.0` with manifest/locales copied to output |
| Determinism check fails only in CI | don't generate files in a build target with timestamps; the CLI packs deterministically from the build output |
