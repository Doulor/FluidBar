# 文件拖动反馈与内容卡片可读性

用户确认跨卡片拖出复制已经生效，实际问题是离开卡片后没有可见拖动标记。本轮按用户明确要求优化拖动反馈，并一起调整文件暂存和剪贴板的内容排版。

## 设计

- 拖动源使用 Windows Shell 的拖动图像，显示图标、文件名、文件数量和复制提示；Shell 管理跨窗口反馈，保持 Copy-only、Esc 取消、原文件和引用均保留。
- 文件列表：文件名优先，最多两行；父目录作为次要信息；移除使用独立小按钮；操作行和文件行分别布局。
- 剪贴板：正文最多两行，底部单独一行显示类型、时间和预览/删除/固定/复制按钮；加大摘要可用宽度，避免操作按钮挤压正文。
- 绘制、命中测试、滚动范围、UIA 共用几何；保持可选插件、双语和字体缩放。

## 排查记录

已验证旧实现可跨出源窗口投递到另一个窗口，Windows Shell 文件夹接收器也能复制 Unicode 文件且保留源文件。尝试真实鼠标注入的临时探针未完成初始化，不能用作产品故障证据；用户进一步确认实际复制有效后移除该探针。后续聚焦缺失的拖动图像，保留无输入注入的跨窗口与真实 Shell 文件复制测试。

Shell 数据对象用 pdtInner 包装原数据时仍会转交私有 SetData，原实现忽略存储，图像回读失败。改为无 inner 的 Shell 数据对象，显式设置文件/Copy 媒体，再由 Shell 保存图像格式后回读通过。只存图像仍不能保证无图像支持的目标可见，原生可见性测试失败；在源 GiveFeedback 中驱动图像管理器后，实际窗口可见并在完成后隐藏。

长剪贴板摘要增加有界双行缓存，避免每帧重复复制长文本；16 KiB 文本的回归先复现 66,112 B/帧，再验证优化后的暖帧分配预算，原文保持完整。
