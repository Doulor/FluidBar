## 保留的 5 项修正

1. `ef40fb9` 位置源改为 KuGou.ini 写入时刻 + 实际播放时长外推（解决恒定慢 2 秒）；
2. `ae981b6` 换曲后从 0 计时（90 秒窗口），丢弃上一首的 ini；
3. `fd25461` 静音不再单独判暂停——要求 ini 也停止推进（修掉 149 秒冻结）；
4. `2683d21` 追赶幅度 ±50% -> ±3%、死区 400 ms（修掉时钟长期 1.05 倍超速）；

## 已证伪的 15 项（勿重复尝试）

偏置自校准、MSAA/ini 新鲜度融合、估计值封顶、窗口 25s、窗口 25s+20s 限制、
文本一致性门限、时长门限判换曲、降低音量阈值、过渡按播放时长、去掉变速追赶、
死区 150ms、连续比例控制（±2% 无死区）、暂停 5 秒隐藏媒体页、换曲后 5 秒写入屏蔽、
过渡按播放时长（重复验证）。

## 已知剩余问题

- **切歌瞬间**（约 1/10 首）会出现 3-19 秒偏差：酷狗在切歌后约 3 秒会把上一首的位置写入 ini，
  而这段时间没有可信的绝对时间源；
- 每 30 秒窗口内有 ±1-3 秒的漂移，靠下一次 ini 写入拉回。

## 根治方案（尚未实施）

进程音频回环帧计数：`ActivateAudioInterfaceAsync` +
`AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK`（KuGou PID），统计渲染帧数，
位置 = 锚点 + 帧数 / 采样率。不依赖 UI 或文件，可同时解决切歌、暂停、seek、最小化。
建议先"影子运行"：并行记录两套结果，连续 30 分钟误差 < 0.2 秒再切主路径。
