# FluidBar marketplace — publishing, review & indexing

This directory holds the **sample signed index** used for onboarding, client integration and tests. The real
marketplace index is generated by CI, never hand-edited. JSON Schemas now live in the repo root
[`schemas/`](../../schemas) (co-reviewed with the Lead).

## Files

| File | Generated? | Purpose |
|---|---|---|
| `index.json` | by `fluidbar-plugin sign-index` / CI | signed root index: latest version per plugin, listing metadata, keys, signatures |
| `keys.json` | by the signer | informational key list (clients trust compiled-in/HSM-injected keys, not this file) |
| `index.payload.json` | hand-authored input | unsigned index payload used to regenerate the sample |

The sample index in this directory is signed with a **throwaway P-256 key generated at generation time**
(the private key is discarded, only the public key is in `keys.json`/`index.json`). It exists so the App/UI can
be developed against a realistic, signature-valid document. Production keys live in an HSM/KMS and never enter
this repository.

Regenerate the sample (schema-valid, re-signed):

```powershell
dotnet run --project src/FluidBar.Cli -- sample-index --payload marketplace/index.payload.json --out-dir marketplace
```

Verify it from code: `MarketplaceIndexParser.Parse` + `IndexSignatureVerifier` (see
`tests/FluidBar.Sdk.Tests/SampleMarketplaceIndexTests.cs`).

## Repository topology

```
fluidbar/FluidBar            App + SDK + schemas + CLI + built-in plugins (this repo)
fluidbar/plugins             community plugin monorepo: plugins/<id>/ (source, manifest, locales, tests)
fluidbar/marketplace         generated index + shards (Pages branch/site); normal PRs never edit it
GitHub Releases (plugins)    fluidbar-plugin-<id>-<version>.fbp + signature.json (detached) + SBOM
```

Index hosting: GitHub Pages (primary), `raw.githubusercontent.com` fallback, plus a bundled bootstrap index in
the installer so first run works offline. Package downloads are direct `releases/download` URLs (302 to a CDN,
no GitHub API quota). Clients verify the index signature before trusting any hash/URL.

## Current governance reality: one maintainer (Doulor)

The project currently has a single maintainer, **Doulor**. The pipeline is optimised for that reality instead
of pretending a committee exists:

```
contributor PR (plugins/<id>/ source)
  → CI on PR: validate manifest + schema, build, tests, pack (dry run), policy/secret scan
  → Doulor review (single reviewer; high-risk capabilities need a written acceptance note in the PR)
  → squash merge
  → publish workflow: build → sign (KMS/HSM, OIDC) → GitHub Release → regenerate + sign index → deploy Pages
  → post-publish verification (re-download, re-verify hash/signature/index) → PR comment with release URL, hash, keyId
```

- **Single reviewer:** no second reviewer is required. For high-risk capabilities (`network: "*"`,
  `shell.execute`, `files.write` outside `$PLUGIN_DATA`, `process.spawn`, `registry.write`) Doulor records the
  acceptance reason in the PR and in the release notes/advisories.
- **SLA:** first review ≤ 5 business days; malware report → `status: blocked` ≤ 24 h; takedown ≤ 72 h.
- **Merge → visible target:** < 10 minutes (build 2–4 min + Pages deploy 1–2 min + cache 5 min).
- **Build from reviewed source, never author-uploaded binaries.** The release asset is CI-built; a contributor
  cannot replace it after review.
- **Future community governance** (trigger: ≥ 3 external contributors and ≥ 20 monthly active plugins):
  CODEOWNERS partition, two reviewers for high-risk capability changes, review rotation, and a public
  rejection/appeal record. Until then, **no voting or committee** is introduced.

## Trust and signing model

- `.fbp` package = deterministic ZIP (`manifest.json`, `plugin/`, `locales/`, `assets/`, `LICENSE`,
  `README.md`, `checksums.json`), SHA-256 pinned in the index.
- Detached `signature.json` sits next to the package (never inside it) and covers the package SHA-256:
  marketplace countersignature is **required**; an author/publisher signature is optional and pinned on first
  install (TOFU, key change requires explicit consent).
- Algorithm: **ECDSA P-256 + SHA-256**, IEEE P1363 signature form, SPKI public keys.
- Key rotation/revocation: `keys.json` carries `keyId`, validity window and `revokedAt`; clients refuse revoked
  keys and warn about already-installed plugins.
- **No sandbox claim:** in-process plugins run with the user's full rights. Capabilities in the manifest are
  disclosure/consent only. Review + CI build + signatures + hashes are the trust boundary, not runtime limits.
- Blocking/yanking: `status: blocked` (client disables installed instance) and `version.yanked` (single version,
  reason required). Release assets are never deleted (forensics).

## Contributor workflow (local → PR → live)

```powershell
# 1. build the plugin (SDK reference: Private=false + EnableDynamicLoading=true)
dotnet build plugins/samples/FluidBar.Plugins.SampleRich

# 2. validate exactly what CI validates (same CLI)
dotnet run --project src/FluidBar.Cli -- validate --plugin plugins/samples/FluidBar.Plugins.SampleRich/bin/Debug/net10.0
dotnet run --project src/FluidBar.Cli -- policy   --plugin plugins/samples/FluidBar.Plugins.SampleRich/bin/Release/net10.0

# 3. package deterministically and check the hash
dotnet run --project src/FluidBar.Cli -- pack --plugin plugins/samples/FluidBar.Plugins.SampleRich/bin/Release/net10.0 --out artifacts/sample-rich-1.0.0.fbp

# 4. open a PR against fluidbar/plugins; CI re-runs the same commands
```

A contributor can do everything except publish without a signing key or maintainer involvement. `validate`/
`pack`/`policy` are network-free; `sign` requires the CI KMS/HSM key and is not run by contributors.

## CI pipeline (`\.github/workflows/marketplace.yml`)

| Trigger | Job | What happens |
|---|---|---|
| PR touching `plugins/**`, `schemas/**`, plugin-platform code or this workflow | `validate` | restore .NET 10 → build tooling + plugins Release → `dotnet test` SDK + PluginHost suites (includes the offline publish/install E2E) → JSON schemas parse → per plugin `validate` + `policy` + pack twice with identical SHA-256 → strict-manifest negative check |
| push to `main` / `workflow_dispatch` with publish=true | `publish` (environment `marketplace-publish`, required reviewer) | build Release → pack + sign every plugin (`publish-prepare` from a protected signing-key secret) → regenerate signed `index.json` + per-plugin shards + `keys.json` → `verify-index` post-generation gate → upload packages + self-contained site artifacts → deploy GitHub Pages |

- The index here is **generated**, never hand-edited: `fluidbar-plugin publish-prepare --plugins-root plugins/samples --artifacts artifacts/plugins --marketplace marketplace-site --key-id <id> --key-env MARKETPLACE_SIGNING_KEY_PEM`.
- **Pages fallback:** if Pages is unavailable (forks, private mirrors, incidents), download the
  `marketplace-site` workflow artifact and host it on any static host — the index is self-contained
  (`index.json` + `keys.json` + `plugins/*.json`). The `marketplace-packages` artifact holds the `.fbp` files.
- No private keys in the repository: `MARKETPLACE_SIGNING_KEY_PEM` is a placeholder environment secret;
  rotation/revocation is documented in [`docs/plugin/signing-and-keys.md`](../docs/plugin/signing-and-keys.md).
- Runbook (merge → live < 10 min, rollback, incidents): [`docs/plugin/publish-runbook.md`](../docs/plugin/publish-runbook.md).
- Review checklist: [`docs/plugin/review-checklist.md`](../docs/plugin/review-checklist.md).

Local rehearsal without GitHub (also used by `MarketplaceEndToEndTests`):

```powershell
dotnet run --project src/FluidBar.Cli -- keygen --out artifacts/rehearsal-key.pem
dotnet run --project src/FluidBar.Cli -- publish-prepare --plugins-root plugins/samples --artifacts artifacts/plugins `
  --marketplace marketplace-site --key artifacts/rehearsal-key.pem --key-id rehearsal-2026 --configuration Release
dotnet run --project src/FluidBar.Cli -- verify-index --marketplace marketplace-site
dotnet test tests/FluidBar.PluginHost.Tests --filter "FullyQualifiedName~MarketplaceEndToEnd"
```

The committed `index.json`/`keys.json` in this directory are the **sample** (throwaway-key) catalog used for
client/UI development and the signed-index regression test; CI writes the real catalog to Pages.

## Definition of done for a plugin PR

- [ ] Manifest schema-valid (strict) and semantically valid (`validate`/`policy` exit 0)
- [ ] Builds on net10.0, `EnableDynamicLoading=true`, no `FluidBar.Sdk.dll` in the package
- [ ] Forbidden references absent (WPF/Avalonia/WebView2/FluidBar.App/host assemblies; scanned by file,
      assembly definition and `AssemblyReference` rows + deps.json)
- [ ] `en-US` locale complete; declared locales parse and have placeholder parity
- [ ] Deterministic package runs `pack` twice with identical SHA-256
- [ ] At least one smoke test: load → start → stop → unload in the plugin-host harness, ALC WeakReference dead
- [ ] README, LICENSE, owner (publisher) and repository URL present; no obfuscation, no self-update, no secrets
- [ ] Every high-risk capability has a plain-language `reason`; capability expansion is called out in the PR
- [ ] Changelog entry; version strictly greater than the published version
