# FluidBar marketplace — publishing, review & indexing

This directory holds the **signed sample index** used for onboarding, client integration and tests. The
production index is generated by CI from reviewed sources and is never hand-edited.

## Files

| File | Generated? | Purpose |
|---|---|---|
| `index.json` | by `fluidbar-plugin publish-prepare` / CI | signed root index: latest version per plugin, listing metadata, keys, signatures |
| `keys.json` | by the signer | informational key list (clients trust the compiled-in public key, not this file) |
| `index.payload.json` | historical input | unsigned payload kept for tooling history; do not hand-edit a signed index |

The sample packages are built, packed and signed by CI with the production marketplace key
`fluidbar-marketplace-2026`. The private half exists only in the protected GitHub environment secret
`MARKETPLACE_SIGNING_KEY_PEM` (and the maintainer's offline backup); it is never committed or downloaded by
clients. The public key is pinned in the app and also published in `keys.json`.

## Hosting and package layout

- Marketplace index: `https://fluidbar.doulor.cn/market/index.json` (Cloudflare Pages project `fluidbar`).
- One GitHub Release per plugin version: tag `plugin-<id>-v<version>`, assets `<id>-<version>.fbp` and
  `<id>-<version>.fbp.sig.json`.
- The signed index points at
  `https://github.com/Doulor/FluidBar/releases/download/plugin-<id>-v<version>/<file>`.
- Clients verify the index signature first, then the index-advertised SHA-256/size, then the detached package
  signature, before exposing an install.

## Pipeline

```
PR / push under plugins/, schemas/, marketplace/ or tooling
  → validate: build, SDK + PluginHost tests, schema parse, policy, deterministic pack
  → publish: pack + sign, regenerate index + shards + keys, verify signature, upload versioned Releases
  → deploy: build website, merge signed index into dist/market, deploy Cloudflare Pages
```

See [publish-runbook.md](../docs/plugin/publish-runbook.md) for required environment secrets and rollback steps.

## Contributor workflow (local → PR → live)

```powershell
# 1. build the plugin (SDK reference: Private=false + EnableDynamicLoading=true)
dotnet build plugins/samples/FluidBar.Plugins.SampleRich

# 2. validate exactly what CI validates (same CLI)
dotnet run --project src/FluidBar.Cli -- validate --plugin plugins/samples/FluidBar.Plugins.SampleRich/bin/Debug/net10.0
dotnet run --project src/FluidBar.Cli -- policy   --plugin plugins/samples/FluidBar.Plugins.SampleRich/bin/Release/net10.0

# 3. package deterministically and check the hash
dotnet run --project src/FluidBar.Cli -- pack --plugin plugins/samples/FluidBar.Plugins.SampleRich/bin/Release/net10.0 --out artifacts/sample-rich-1.0.0.fbp

# 4. open a PR against fluidbar/plugins; CI re-runs the same commands
```

A contributor can do everything except publish without a signing key or maintainer involvement. `validate`/
`pack`/`policy` are network-free; `sign` requires the CI KMS/HSM key and is not run by contributors.

## CI pipeline (`.github/workflows/marketplace.yml`)

| Trigger | Job | What happens |
|---|---|---|
| PR touching `plugins/**`, `schemas/**`, plugin-platform code or this workflow | `validate` | restore .NET 10 → build tooling + plugins Release (build output derived via MSBuild `TargetPath`, no hardcoded TFM path) → `dotnet test` SDK + PluginHost suites (includes the offline publish/install E2E) → JSON schemas parse → per plugin `validate` + `policy` + pack twice with identical SHA-256 → strict-manifest negative check |
| push to `main` / `workflow_dispatch` with publish=true | `publish` (environment `marketplace-publish`, required reviewer) | fail fast on missing config → build Release → pack + sign every plugin (`publish-prepare` from a protected signing-key secret) → regenerate signed `index.json` + per-plugin shards + `keys.json` → `verify-index` post-generation gate → upload packages + self-contained site artifacts |
| after `publish` | `deploy` (environment `github-pages`; skipped only when `MARKETPLACE_DEPLOY_PAGES=false`) | download `marketplace-site` → `actions/configure-pages` → `upload-pages-artifact` → `deploy-pages`; failure is visible (no silent fallback) |

Required publish configuration (the workflow fails fast if missing): environment `marketplace-publish` with secret
`MARKETPLACE_SIGNING_KEY_PEM`; repository/environment variables `MARKETPLACE_ARTIFACT_BASE_URL`,
`MARKETPLACE_BASE_URL`, `MARKETPLACE_SIGNING_KEY_ID`; optional `MARKETPLACE_PLUGINS_ROOT`
(default `plugins/samples` in this repo) and `MARKETPLACE_DEPLOY_PAGES`. No placeholder URL defaults are used in
publish mode. Actions are pinned to full commit SHAs (tag in the trailing comment).

- The index here is **generated**, never hand-edited: `fluidbar-plugin publish-prepare --plugins-root plugins/samples --artifacts artifacts/plugins --marketplace marketplace-site --key-id <id> --key-env MARKETPLACE_SIGNING_KEY_PEM`.
- **Publishing scope:** this repository publishes the `plugins/samples/` demo/reference plugins for pipeline
  verification; the real catalogue lives in the `fluidbar/plugins` monorepo (`plugins/<id>/`) and is published by
  setting `MARKETPLACE_PLUGINS_ROOT=plugins` (or pointing the workflow at that checkout).
- **Pages / artifact-only:** with Pages enabled the `deploy` job publishes the site. If Pages is intentionally
  unavailable (forks, mirrors, incidents), set `MARKETPLACE_DEPLOY_PAGES=false`; the `marketplace-site` workflow
  artifact is then the published output and can be hosted on any static host (the index is self-contained:
  `index.json` + `keys.json` + `plugins/*.json`). `marketplace-packages` holds the `.fbp` files. There is no
  silent fallback: a failing deploy when Pages is enabled fails the run.
- No private keys in the repository: `MARKETPLACE_SIGNING_KEY_PEM` is a placeholder environment secret;
  rotation/revocation is documented in [`docs/plugin/signing-and-keys.md`](../docs/plugin/signing-and-keys.md).
- Runbook (merge → live < 10 min, required variables, SHA-pinning policy, rollback, incidents):
  [`docs/plugin/publish-runbook.md`](../docs/plugin/publish-runbook.md).
- Review checklist: [`docs/plugin/review-checklist.md`](../docs/plugin/review-checklist.md).

Local rehearsal without GitHub (also used by `MarketplaceEndToEndTests`):

```powershell
dotnet run --project src/FluidBar.Cli -- keygen --out artifacts/rehearsal-key.pem
dotnet run --project src/FluidBar.Cli -- publish-prepare --plugins-root plugins/samples --artifacts artifacts/plugins `
  --marketplace marketplace-site --key artifacts/rehearsal-key.pem --key-id rehearsal-2026 --configuration Release
dotnet run --project src/FluidBar.Cli -- verify-index --marketplace marketplace-site
dotnet test tests/FluidBar.PluginHost.Tests --filter "FullyQualifiedName~MarketplaceEndToEnd"
```

The committed `index.json`/`keys.json` in this directory are the **sample** (throwaway-key) catalog used for
client/UI development and the signed-index regression test; CI writes the real catalog to Pages.

## Definition of done for a plugin PR

- [ ] Manifest schema-valid (strict) and semantically valid (`validate`/`policy` exit 0)
- [ ] Builds on net10.0, `EnableDynamicLoading=true`, no `FluidBar.Sdk.dll` in the package
- [ ] Forbidden references absent (WPF/Avalonia/WebView2/FluidBar.App/host assemblies; scanned by file,
      assembly definition and `AssemblyReference` rows + deps.json)
- [ ] `en-US` locale complete; declared locales parse and have placeholder parity
- [ ] Deterministic package runs `pack` twice with identical SHA-256
- [ ] At least one smoke test: load → start → stop → unload in the plugin-host harness, ALC WeakReference dead
- [ ] README, LICENSE, owner (publisher) and repository URL present; no obfuscation, no self-update, no secrets
- [ ] Every high-risk capability has a plain-language `reason`; capability expansion is called out in the PR
- [ ] Changelog entry; version strictly greater than the published version
